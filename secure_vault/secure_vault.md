# SecureVault — Project Guide

> **The evolving project** for the Flutter Forge course.
> Every module adds a new layer — by Module 08 you have a production-ready, security-first cross-platform app.

## First-time Setup

The `lib/` source code is ready but the platform folders (`android/`, `ios/`, `web/`, etc.) need to be generated by the Flutter CLI on your machine. Run this once:

```bash
cd path/to/flutter\ forge/secure_vault
bash setup.sh
```

The script will:
1. Create a temporary Flutter project to get the platform folders
2. Copy `android/`, `ios/`, `web/`, `macos/`, `windows/`, `linux/` into this project
3. Run `flutter pub get`
4. Run `build_runner` for code generation (Riverpod, Drift, Freezed)

After that you never need to run it again.

## Running the App

```bash
flutter run -t lib/main.dart -d chrome          # Web (fastest to verify)
flutter run -t lib/main.dart -d macos           # macOS desktop
flutter run -t lib/main.dart                    # Mobile (pick device)

# Run tests
flutter test
flutter analyze
```

## Architecture

```
lib/
├── core/
│   ├── config/      → AppConfig, Flavor enum
│   ├── network/     → Dio client, interceptors
│   ├── security/    → VaultCrypto, MasterKeyService, key derivation
│   └── storage/     → flutter_secure_storage provider
├── features/
│   ├── auth/        → LoginScreen, BiometricAuth, AuthState
│   ├── vault/       → VaultItem, VaultRepository, VaultNotifier, screens
│   ├── generator/   → Password generator
│   └── settings/    → Settings screen
├── router/          → GoRouter config, AppRoutes constants
└── shared/
    ├── theme/       → AppTheme (light + dark, Material 3)
    └── widgets/     → AppShell (adaptive navigation)
```

## Security Notes

- Passwords are NEVER stored in plaintext — always encrypted with AES-256-GCM
- The encryption key lives in memory only; serialised salt lives in OS keychain
- `TODO (Module 05)` comments mark every place where encryption wiring is pending
- Do not remove the `TODO` markers until Module 05 is complete

## How to Build This Project (Module by Module)

The project is pre-scaffolded — the folder structure and files are already there. Your job each module is to **fill in the TODOs** and wire things up. Here's exactly what to do after finishing each module's doc.

---

### After Module 01 — Fundamentals

The screens already exist. Your tasks:

- Open each screen in `lib/features/` and read through it fully
- Run the app (`flutter run -d chrome`) and make sure it renders without errors
- Modify `VaultItemCard` to change the colors or layout — just to feel how widgets work
- Add a new field to `VaultItem` (e.g., `tags`) and show it in the card
- **Goal:** the app runs, you can navigate between screens, you understand every widget used

---

### After Module 02 — State Management

The providers exist in `lib/features/vault/presentation/providers/vault_providers.dart` but are hand-wired. Your tasks:

- Add `flutter_riverpod` and `riverpod_annotation` to `pubspec.yaml` (already there — just run `flutter pub get`)
- Run `dart run build_runner build` to generate the `.g.dart` files
- Wrap `main.dart` with `ProviderScope` (already done — verify it's there)
- Add 3 fake `VaultItem`s to `InMemoryVaultRepository` so the list is not empty when you open the app
- Make the search bar in `VaultListScreen` actually filter the list
- **Goal:** the vault list shows items reactively, search works, add/delete updates the UI instantly

---

### After Module 03 — Navigation

The router exists in `lib/router/app_router.dart` but has no auth guard. Your tasks:

- Add a simple `authStateProvider` (a `StateProvider<bool>` — `false` = locked, `true` = unlocked)
- Add the `redirect` callback to `GoRouter` that sends unauthenticated users to `/login`
- Wire the Login screen's Unlock button to set `authStateProvider` to `true`
- Wire the Settings screen's Lock Vault button to set it back to `false`
- Verify the redirect works: open the app → lands on `/login` → unlock → goes to `/vault` → lock → back to `/login`
- **Goal:** navigation is fully working with a real auth gate (fake auth for now, real in Module 05)

---

### After Module 04 — Data & Storage

The repository interface exists but only has an in-memory implementation. Your tasks:

- Add `drift`, `sqlite3_flutter_libs`, `path_provider`, `path` to `pubspec.yaml` (already in the file)
- Create `lib/core/database/app_database.dart` with the `VaultItems` table (see `docs/04_data_storage/README.md`)
- Create `LocalVaultRepository` implementing `VaultRepository` using Drift DAOs
- In `vault_providers.dart`, change `vaultRepositoryProvider` to return `LocalVaultRepository` instead of `InMemoryVaultRepository`
- Replace the hand-written `VaultItem` model with a Freezed version
- Run the app, add items, close and reopen — items should persist
- **Goal:** data survives app restarts, full CRUD working against real SQLite

---

### After Module 05 — Security

This is the most important module. There are `TODO (Module 05)` comments scattered across several files — find and resolve every single one. Your tasks:

- Implement `lib/core/security/vault_crypto.dart` (AES-256-GCM encrypt/decrypt)
- Implement `lib/core/security/key_derivation.dart` (PBKDF2)
- Implement `lib/core/security/master_key_service.dart` (key in memory only)
- Wire `MasterKeyService.unlock()` into `LoginScreen` (replace the fake navigation)
- Wire `VaultCrypto.encrypt()` into `VaultItemFormScreen` before saving
- Wire `VaultCrypto.decrypt()` into `VaultItemDetailScreen` before displaying
- Implement `ClipboardService` with 30-second auto-clear
- Add `AppLifecycleObserver` to `main.dart` for auto-lock on background
- Add biometric auth in `LoginScreen` (replace the snackbar placeholder)
- **Goal:** zero plaintext passwords anywhere in storage or logs, vault locks on background

---

### After Module 06 — Cross-Platform

The `AppShell` already adapts between mobile and desktop. Your tasks:

- Test on at least 3 platforms: `flutter run -d chrome`, `-d macos`, and a mobile simulator
- Fix anything that looks broken on each platform (font sizes, spacing, overflow)
- Add master-detail layout in `VaultListScreen` for screens wider than 700px
- Add `window_manager` sizing in `main.dart` for desktop
- Add `Cmd/Ctrl+N` keyboard shortcut to open the new item form
- Add hover effect on `VaultItemCard` for web/desktop
- **Goal:** the app looks intentional and native on all platforms, not just "mobile stretched to desktop"

---

### After Module 07 — Testing

Tests already exist for `VaultItemCard`. Your tasks:

- Write unit tests for `VaultCrypto` (encrypt/decrypt roundtrip, wrong key throws)
- Write unit tests for `VaultNotifier` (add/delete/update with a mock repository)
- Write widget tests for `LoginScreen` (form validation, button tap)
- Write widget tests for `VaultListScreen` (empty state, items shown, search filters)
- Run `flutter test --coverage` and check coverage is above 80% on `lib/`
- **Goal:** you can refactor anything with confidence

---

### After Module 08 — Deployment

- Create `.github/workflows/ci.yml` (see `docs/08_deployment/README.md` for the full template)
- Push to GitHub — the workflow should run automatically
- Verify the Android APK artifact appears in GitHub Actions
- **Goal:** every push to `main` builds all platforms automatically
